# Эталонная разметка

Эталон нужен, чтобы проверять не только устойчивость оценок, но и их правильность. Пять отчётов Сбера по
спецификации проекта разметила модель Claude Opus 5: по тексту отчёта, не видя ответов других моделей. Поэтому
файлы называются `…_CLAUDE.csv`. Автор проверил вручную два отчёта целиком и все 11 спорных клеток трёх отложенных
отчётов и нашёл одну ошибку разметки (записка, раздел 2; приложения, раздел З).

| файл | что внутри |
|---|---|
| [2022_q4_CLAUDE.csv](2022_q4_CLAUDE.csv), [2026_q2_CLAUDE.csv](2026_q2_CLAUDE.csv) | отчёты, на которых настраивалась спецификация; проверены автором целиком |
| [2023_q2_CLAUDE.csv](2023_q2_CLAUDE.csv), [2024_q4_CLAUDE.csv](2024_q4_CLAUDE.csv), [2025_q3_CLAUDE.csv](2025_q3_CLAUDE.csv) | отложенные отчёты: при настройке не разбирались, эталон по ним записан 22.09, до финального прогона |
| [ХОЛДАУТ_ХЕШИ_22.09.txt](ХОЛДАУТ_ХЕШИ_22.09.txt) | контрольные суммы SHA-256 трёх отложенных файлов, записанные 22.09 в 17:39, до просмотра ответов моделей на этих отчётах |
| [ПРЕДРЕГИСТРАЦИЯ_ПОРОГА.md](ПРЕДРЕГИСТРАЦИЯ_ПОРОГА.md) | процедура порога отказа, записанная 18.09 до расчёта (результат — приложения, раздел Е) |

В каждом CSV 24 строки, по одной на показатель. Колонки: обозначение показателя, блок, название, тип (поток или
состояние), короткое правило спецификации, оценка от −2 до +2, цитата из отчёта и комментарий. Комментарий,
который начинается со слова «СПОРНО», отмечает клетку, где правило допускает два прочтения; такие клетки
считаются и отдельно ([../code/src/silver_gold.py](../code/src/silver_gold.py)). Цитаты эталона проверены той же
программой, что и цитаты моделей.

## Почему в двух файлах пути ведут вне репозитория

Оба файла записаны до финального прогона и после этого не менялись, иначе они перестали бы быть доказательством.

- В `ХОЛДАУТ_ХЕШИ_22.09.txt` стоят пути `_АНДРЕЙ/4_разметка/…`: 22.09 файлы лежали в рабочей папке автора, которая
  в репозиторий не входит. Сами файлы перенесены сюда без изменений. Скрипт [audit.py](../code/src/audit.py)
  (проверка A4) сравнивает суммы по имени файла. Проверить вручную можно так:

  ```bash
  grep CLAUDE ХОЛДАУТ_ХЕШИ_22.09.txt | sed 's#_АНДРЕЙ/4_разметка/##' | sha256sum -c
  ```

- В `ПРЕДРЕГИСТРАЦИЯ_ПОРОГА.md` упомянуты заметки автора с выводом формул (`_АНДРЕЙ/3_знания/…`). Они тоже не
  входят в репозиторий; процедура и её результат изложены в приложениях, раздел Е, код —
  [abstain.py](../code/src/abstain.py) и [abstain_run.py](../code/src/abstain_run.py). В записи 18.09 ошибкой
  названо расхождение с ручной разметкой автора, а фактически эталоном служит разметка Claude Opus 5; это
  отступление описано в приложениях, раздел З, пункт 10.
