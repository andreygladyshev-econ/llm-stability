# Код и данные

Здесь лежит всё, что нужно, чтобы пересчитать числа записки и заново собрать таблицу оценок, векторы и рисунки по
сохранённым ответам моделей. Запускать сами модели для этого не нужно.

## Состав

| папка или файл | что внутри |
|---|---|
| [src](src/) | скрипты на Python |
| [specs](specs/) | все проверенные версии спецификации и запросы к модели; v1 совпадает со спецификацией заказчика, итоговая версия [v7_extract.md](specs/v7_extract.md) |
| [raw](raw/) | ответы моделей, по одному файлу JSON на прогон; имя файла содержит модель, версию спецификации, режим, отчёт и номер прогона; в поле meta записаны параметры прогона (температура, порядок показателей, провайдер, время, стоимость); подпапки `_archive` (пробные запуски при настройке) и `_failed` (прогоны, завершившиеся ошибкой) в расчётах не участвуют |
| [raw_qwen_bf16](raw_qwen_bf16/) | 21 ответ облачной Qwen 27B без сжатия (bf16); серия прервана из-за медленного провайдера, ответы используются в сравнении сжатия (final_checks.py, блок E) |
| [text_v2](text_v2/) | текст отчётов, распознанный моделью со зрением и сверенный со скрытым текстовым слоем PDF; по нему получены все итоговые оценки |
| [text](text/) | текст отчётов, распознанный Tesseract; использовался в первых опытах |
| [text_pdf](text_pdf/) | скрытый текстовый слой PDF (Сбер) и текст PDF других банков с контрольными суммами; по нему цитаты таблицы переписываются посимвольно (src/pdf_quotes.py), выгрузка: src/export_pdf_text.py |
| [queues](queues/) | описания серий прогонов: модели, версии спецификации, режимы |
| [notes](notes/) | соответствие обозначений отчётов исходным PDF; примечания ручной проверки итоговой таблицы (примечания_проверки.json) |
| [logs/cloud_ledger.jsonl](logs/cloud_ledger.jsonl) | стоимость каждого облачного запроса |
| [выводы](выводы/) | сохранённые выводы всех расчётов, на которые ссылаются записка и приложения |
| [requirements.txt](requirements.txt) | версии библиотек |

Эталонная разметка лежит в соседней папке [../эталон](../эталон/).

## Как пересчитать

Нужен Python 3.12. Из этой папки:

```bash
python -m pip install -r requirements.txt
python src/audit.py
python src/final_checks.py
python src/deep_analysis.py
python src/deep_analysis2.py
python src/registry_checks.py
python src/qoq_check.py
python src/ocr_order_check.py
python src/build_submission.py
python src/figures.py
```

Каждый скрипт анализа печатает результат в консоль; сохранённые копии этих выводов лежат в папке
[выводы](выводы/). Можно запускать отдельные блоки, например `python src/deep_analysis2.py 16 17`. Скрипты
`build_submission.py` и `figures.py` при запуске из папки сдачи пишут результат в `код/пересборка/`, чтобы не
затирать сданные файлы. Пересобранные таблицы и векторы совпадают со сданными побайтно. Рисунки совпадают по данным;
пиксели зависят от шрифта (Helvetica Neue на macOS, Arial или Liberation Sans в других системах). Проверка
распознавания (`ocr_order_check.py`) берёт PDF из папки `задание/SBER` в корне репозитория.

## Какой скрипт что даёт

| скрипт | что считает |
|---|---|
| [build_submission.py](src/build_submission.py) | таблица оценок с обоснованиями, цитатами и примечаниями, векторы (CSV и JSON), замеры устойчивости, оценки всех прогонов |
| [pdf_quotes.py](src/pdf_quotes.py) | перенос цитаты на текст PDF: буквы из текстового слоя, пробелы и границы ячеек из распознанного текста; проверка посимвольного совпадения |
| [figures.py](src/figures.py) | рисунки 1–10 (1–3 в записке, 4–10 в приложениях); номер файла равен номеру рисунка |
| [audit.py](src/audit.py) | проверка данных: одна версия спецификации во всех прогонах, по 5 прогонов на отчёт, все ответы разобраны, нет обрезанных ответов и чужого кэша, итоговая оценка равна и медиане, и самому частому значению, контрольные суммы эталона не изменились, цитаты модели найдены в тексте (A6), цитаты сданной таблицы совпадают с текстом PDF посимвольно (A7) |
| [final_checks.py](src/final_checks.py) | блок A: повторяемость в облаке; B: хрупкие клетки при разных возмущениях; C: сколько перестановок нужно; D: сравнение моделей с интервалами; E: одна модель на ноутбуке и в облаке; F: порог отказа по заранее записанной процедуре; G: независимость клеток одного отчёта |
| [deep_analysis.py](src/deep_analysis.py) | блок 1: модели и классы оборудования; 2: показатели, трудные для всех сильных моделей; 3: согласие моделей и хрупкость; 4: ошибки против эталона; 5: причины хрупкости числовых показателей; 6: суммы по отчётам Сбера и альтернативные пороги; 7: ложные нули; 8: отчёты для настройки против отложенных; 9: время и стоимость |
| [deep_analysis2.py](src/deep_analysis2.py) | блок 10: хрупкость с учётом трудности показателей; 11: запасной вариант «программа не посчитала»; 12: правила итогового вывода; 13: порог отказа только на отложенных отчётах; 14: размышление; 15: контрольный прогон при T=0,7; 16: три сильные модели на 19 отчётах; 17: ошибки против хрупкости в итоговом режиме; 18: версии 7 и 10; 19: Opus и Grok; 20: объём работы; 21: лестница стабилизации (рисунок 1); 22: форма записи правил и отдельные правки; 23: числа, которых нет в тексте отчёта; 24: хрупкость и ошибки против эталона (рисунок 3) |
| [registry_checks.py](src/registry_checks.py) | относительные пороги стоимости риска; операционные расходы без операционного дохода |
| [qoq_check.py](src/qoq_check.py) | ячейки, где базой сравнения мог стать прошлый квартал вместо прошлого года |
| [ocr_order_check.py](src/ocr_order_check.py) | качество распознавания по скрытому слою PDF: доля найденных чисел и порядок столбцов в строках таблиц |
| [report.py](src/report.py) | загрузка ответов, применение правил программы, проверка цитат; при запуске строит сводную таблицу всех конфигураций (сохранённая копия: [выводы/ЖУРНАЛ_РЕЗУЛЬТАТОВ.md](выводы/ЖУРНАЛ_РЕЗУЛЬТАТОВ.md)) |
| [score_rules.py](src/score_rules.py) | правила оценки 17 числовых показателей: выбор периода, расчёт изменения, пороги |
| [abstain.py](src/abstain.py) | процедура порога отказа с гарантией на долю ошибок |
| [silver_gold.py](src/silver_gold.py) | чтение эталонной разметки |

Скрипты [night.py](src/night.py) и [cloud.py](src/cloud.py) запускали серии прогонов на ноутбуке (через LM Studio)
и в облаке (через OpenRouter), [ocr_v2.py](src/ocr_v2.py) распознавал сканы. Для пересчёта они не нужны. Для новых
прогонов понадобятся LM Studio с моделью Qwen 3.8 27B (MLX, 4 бита) или собственный ключ OpenRouter; ключ в код не
включён.
